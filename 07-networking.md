# Глава 7. Сети

Часть задач — это не файл, а **сервис**: тебе дают адрес `IP:ПОРТ`, к которому надо подключиться.
Сервер что-то спрашивает, ты отвечаешь — и за правильный диалог получаешь флаг. Эта глава про то,
как подключаться и как **автоматизировать** общение, когда руками уже неудобно.

---

## 7.1. Минимум теории: IP, порт, TCP

- **IP-адрес** — адрес машины в сети (`10.0.0.5`). **Порт** — номер «двери» на этой машине
  (`31337`). Вместе `IP:ПОРТ` однозначно указывают на конкретный сервис.
- **TCP** — надёжное соединение-«труба»: что отправил, то и дойдёт по порядку. Большинство
  CTF-сервисов — TCP. (UDP — без гарантий, встречается реже.)
- Сервис по адресу обычно работает так: **читает** твой ввод, что-то считает, **пишет** ответ.
  Твоя задача — понять протокол общения и дать то, что он ждёт.

---

## 7.2. `nc` (netcat) — подключиться и поговорить руками

`nc` (netcat) — «швейцарский нож» для сетевых соединений. Подключение к сервису:

```bash
nc 10.0.0.5 31337          # подключиться к IP на порт 31337
```

После подключения просто печатаешь ответы и жмёшь Enter. Сервер пишет — ты читаешь прямо в
терминале. Этого достаточно для простых диалоговых задач.

Полезные варианты:

```bash
nc -v 10.0.0.5 31337       # -v = подробно (видно, установилось ли соединение)
echo "42" | nc 10.0.0.5 31337          # сразу отправить строку и получить ответ
nc 10.0.0.5 31337 < input.txt          # скормить заготовленный ввод из файла
```

💡 Если задача называется «подключитесь к серверу» и дан `IP ПОРТ` — первым делом просто `nc` туда
и посмотри, что он говорит. Часто сервер сам всё объясняет.

🎯 **Тренировка 19.** Запусти локальный «сервер» в одном терминале (`nc -lvp 9999` — слушать порт
9999) и подключись к нему из другого (`nc 127.0.0.1 9999`). Напиши что-нибудь в одном окне — увидишь
в другом. Так ты поймёшь, что `nc` — это просто «труба» между двумя концами.

## 7.3. Когда руками неудобно — Python `socket`

Если сервер задаёт много вопросов, считает что-то на лету или даёт мало времени — отвечать руками не
успеть. Тогда пишем скрипт. В стандартной библиотеке Python есть всё — модуль `socket`:

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)   # создать TCP-сокет
s.connect(("10.0.0.5", 31337))                           # подключиться (IP, порт)

print(s.recv(1024))          # прочитать до 1024 байт (вопрос сервера)
s.sendall(b"42\n")           # отправить ответ — ОБЯЗАТЕЛЬНО байты и с \n на конце!
print(s.recv(1024))          # прочитать ответ (часто здесь флаг)

s.close()
```

⚠️ Три главные ошибки новичков:
1. **Отправлять строку вместо байтов** — `sendall` принимает `bytes`, пиши `b"..."` или `.encode()`.
2. **Забыть `\n`** в конце — сервер обычно читает «строку до перевода», без `\n` он будет ждать
   вечно.
3. **Читать не вовремя** — если сервер ещё не прислал данные, `recv` подождёт; если прислал больше
   1024 байт — дочитай ещё раз.

### Шаблон «вопрос-ответ в цикле»

Частый случай: сервер задаёт серию задачек (например, «посчитай выражение») и в конце отдаёт флаг.
Автоматизируем:

```python
import socket

s = socket.socket()
s.connect(("10.0.0.5", 31337))

f = s.makefile("rwb")        # удобно читать построчно, как файл

for _ in range(100):         # сервер может гонять много раундов
    line = f.readline()      # прочитать строку-вопрос
    print(line)
    # пример: сервер прислал "12 + 30"
    expr = line.decode().strip()
    answer = str(eval(expr))          # посчитать (eval только для ДОВЕРЕННОГО формата!)
    f.write(answer.encode() + b"\n")  # отправить ответ
    f.flush()                         # ВАЖНО: протолкнуть буфер
    if b"flag" in line:
        break
```

💡 `s.makefile("rwb")` + `readline()` избавляет от возни с `recv` по кусочкам, когда сервер общается
строками. Не забывай `flush()` после записи — иначе ответ «застрянет» в буфере.

🎯 **Тренировка 20.** Напиши свой сервер-«викторину» на `socket` (спрашивает `6*7`, на `42` отвечает
флагом) и клиента, который его проходит автоматически. Это ровно та механика, что на туре: прочитать
→ посчитать → отправить → прочитать флаг.

## 7.4. `pwntools` — если установлен

🔺 `pwntools` — библиотека, которая делает сетевое общение (и pwn-задачи) короче. Проверь, есть ли
она: `python3 -c "import pwn"`. Если есть — удобнее так:

```python
from pwn import *

io = remote("10.0.0.5", 31337)   # подключиться
print(io.recvline())              # прочитать строку
io.sendline(b"42")                # отправить (sendline сам добавит \n)
print(io.recvline())              # прочитать ответ
io.interactive()                  # перейти в ручной режим (дочитать/дописать самому)
```

Полезные методы: `recvline()` (строка), `recvuntil(b":")` (читать до подстроки), `sendline(b"...")`
(отправить со `\n`), `interactive()` (ручной режим). Если `pwntools` нет — всё то же делается на
чистом `socket` из §7.3, просто чуть длиннее.

## 7.5. Разбор сетевых задач «на схему»

Иногда сеть — это не сервис, а **задача на понимание**: дают схему сети или вывод команд и просят
объяснить, почему связь не работает. Полезный минимум команд диагностики:

```bash
ip addr          # какие IP у интерфейсов (мой адрес и маска подсети)
ip route         # таблица маршрутов; есть ли "default via ..." (шлюз в интернет)
ping 10.0.0.1    # доходит ли пакет до адреса
nslookup host    # резолвится ли имя в IP (работает ли DNS)
```

Типичные причины «нет интернета», которые надо уметь читать по выводу:
- нет строки `default via ...` в `ip route` → **не задан шлюз** (локально пингуется, наружу нет);
- `ping шлюза` не проходит → **не та подсеть/маска** или шлюз недоступен;
- пинг по IP работает, а по имени нет → **проблема с DNS** (`nslookup`/`getent` молчит);
- адрес в чужой подсети → машина физически не в той сети.

💡 На муниципале это чаще теоретический блок: читаешь вывод `ip addr`/`ip route`/`ping` и
сопоставляешь симптом с причиной. Выучи четыре пункта выше — обычно их достаточно.

---

## 7.6. Сети: «вижу X → делаю Y»

| Что видишь | Что делать |
|---|---|
| дан `IP ПОРТ`, «подключитесь» | `nc IP ПОРТ`, прочитать, что говорит сервер |
| сервер задаёт один вопрос | ответить руками в `nc` |
| сервер гоняет много раундов / мало времени | скрипт на `socket` (цикл читать-считать-писать) |
| есть `pwntools` | `remote()`, `recvline`/`sendline`, `interactive()` |
| дали схему сети / вывод `ip route` | искать: шлюз, маску, DNS (§7.5) |

> **Итог главы.** Ты умеешь подключаться к сервису через `nc`, автоматизировать диалог на чистом
> `socket` (а если есть — на `pwntools`), не наступать на грабли с байтами/`\n`/`flush`, и читать
> простую сетевую диагностику. Дальше — реверс: как не испугаться скомпилированной программы.
